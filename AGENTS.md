# Working agreement

Before starting an implementation increment, present a step-by-step plan for the
user to review and wait for approval. Approval to scaffold or plan does not
authorize implementing the task runner. Keep work within the approved scope; bring
material changes to the plan back for review before proceeding.

Commit and push when the user authorizes them. Include relevant verification
results and limitations when presenting completed work.

The project targets C++23 on Linux, macOS, and Windows. Prioritize a lean design,
minimal dependencies, and small-system suitability. Keep orchestration in TOML and
procedural logic in programs or scripts. See `docs/design.md` for agreed direction
and proposals, and `docs/next-increment.md` for the pending plan.
